=== DataFragment Packet Format

The portable codec is implemented in `include/nova_link/fragment.h` and
`src/fragment.c`. See `Protocol_Decisions.md` for software ABI decisions.

[cols="1,1,3", options="header"]
|===
| Field | Size | Description
| Header | 1 byte | originID (3 bits), zoneID (3 bits), flags (2 bits)
| seqNum | 1 byte | Independent per-origin/zone sequence, modulo 256
| payload | 0–100 bytes | Application-defined bytes
|===

==== Header Format

[cols="1,1,3", options="header"]
|===
| Bits | Name | Description
| 7–5 | originID | Sender ID 0–7, assigned uniquely by the application
| 4–2 | zoneID | Logical zone 0–7; 0 is shared metadata
| 1 | BURST | Request a bounded extension of a zone window
| 0 | MGMT_LISTEN | Request a metadata slot after a data-zone round
|===

The serialized size is 2–102 bytes. Struct padding is never transmitted. The
transport length (or a PHY adapter's received length) supplies payload length;
there is no separate payload-length field in the RF fragment.

No fragment checksum, application-message ID, fragment index, epoch, or
acknowledgment is defined. A PHY adapter must establish CRC behavior. Larger
application messages need a plugin-owned fragmentation/reassembly format;
the core rejects payloads over 100 bytes. Deduplication does not provide
integrity or guaranteed delivery. MGMT_LISTEN does not change zone routing.
