# Offline replay acceptance

The replay wrapper runs synthetic `NVS1` observations through the portable C
receive engine. It verifies reconstruction, result decisions and link state
without a radio. It refuses real/candidate-PHY observations; passing these
checks establishes no City Theatrical Multiverse RF compatibility.

Use the versioned trace as an explicit receive acceptance scenario:

```sh
python3 tools/replay_multiverse.py examples/multiverse.synthetic.jsonl \
  --end-us 104000 --expect-frames 4 --expect-link lost --summary-only
```

This trace checks reordered assembly, duplicate suppression, a missing delta
base, full recovery, corrupt/unknown integrity and session filtering. The final
clock advance checks loss during silence. All eleven observations assert their
receive result and link state; four committed frames assert exact levels.

Optional JSONL fields describe independent expectations for each observation:

| Field | Meaning |
| --- | --- |
| `expected_result` | Require `ok`, `frame_ready`, `duplicate`, `stale`, `filtered`, `need_full`, `bad_packet`, or `unverified`. |
| `expected_link` | Require `wait_full`, `live`, `recovering`, or `lost` immediately after this observation. |
| `expected_slots_hex` | Compare exact levels if this observation commits a frame; encode 0..512 slots as complete hex bytes. |

An `ok` result means a valid chunk was accepted without committing a complete
frame. `expected_slots_hex` preserves its original snapshot semantics: logs
generated by the simulator include host levels even on observations deliberately
corrupted, filtered or left incomplete. That field alone does **not** assert
delivery. To require delivery at a particular observation, also set
`expected_result` to `frame_ready`. To prohibit delivery, assert the expected
rejection/partial result. Expected levels may use upper- or lowercase hex;
result and link names use the exact lowercase spellings above.

`--expect-frames N` requires exactly N committed frames over the entire trace,
including zero. It detects missing or extra frames without requiring every
observation to carry an assertion. `--expect-link STATE` checks the final link
after `--end-us` (or the last observation when that option is omitted). Existing
`--loss-us`, `--assembly-us`, `--universe` and `--session` settings still select
the model's timing and binding; they are test assumptions, not measured RF
settings.

Missing/extra delivery, unexpected link/result, incorrect levels and malformed
expectations exit with status 2 and a mismatch description. Checks run before
writing `--output`, so a failed acceptance check leaves an existing output
file intact. The capture itself cannot be selected as the output path.

The summary exposes `expected_frames_checked` for level comparisons,
`expected_results_checked` and `expected_links_checked` for per-observation
assertions, and `final_expectations_checked` for the two optional CLI checks.
Level labels on observations that do not commit a frame are never counted as
checked. Other checked counts are zero when those expectations were omitted.
These counts do not measure RF reception, latency or hardware coverage.

Annotations and CLI expectations are opt-in, so older synthetic logs still
replay unchanged. The checked-in example now opts in explicitly. RX tests
also cover missed delivery, extra delivery with identical levels, recovery
after missing bases and silence, expired duplicates that cannot revive a link,
and output preservation on failure. Independent Python `struct`/`zlib` packet
vectors keep these assertions separate from the C synthetic encoder.
