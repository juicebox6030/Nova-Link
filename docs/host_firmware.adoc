=== Host Firmware Architecture (ESP32-S3)

The ESP32-S3 runs the portable base and compiled application, transport, and
service plugins. SPI communication with the CC135x belongs to a transport
plugin's board backend.

==== Key Responsibilities
- Plugin lifecycle and dispatch
- Plugin Fragment deduplication 
- Zone claim management
- Named module composition, dependency ordering, and rollback
- Poll transport plugins before application ticks

==== Workflow
1. Initialize persistent plugin/backend context and the base
2. Start the module manifest; dependencies and declarative zone claims are applied
3. Poll transport plugins for incoming fragments and dispatch through Stream Tracker
4. Tick application/service plugins and send through the active transport plugin
5. Stop modules in reverse dependency order and drain/cancel backend work

The desktop radio transport backend exercises the same lifecycle without SPI
hardware. ESP-IDF SPI/GPIO and physical RF drivers still need implementation and
board validation. See `Development.md` for the installed module API.
